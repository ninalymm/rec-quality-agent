# 回归门禁（M5）设计与实测

## 它挡什么

改坏 prompt / 改错逻辑 / 换模型导致**质量大幅下降**时，CI 要变红。

它**不挡**什么：细微的质量波动（原因见下面的实测）。

## 结构：两关

| 关卡 | 内容 | 成本 | 依赖 |
|---|---|---|---|
| `test` | `pytest`，83 个离线用例 + 覆盖率 ≥60% | 0 | 无（不联网、不需要 key） |
| `regression` | 跑 20 条固定任务，成功率与基线比较 | 约 ¥0.11 | 需要 `DEEPSEEK_API_KEY` |

第二关在 fork 场景（没有 secret）会跳过并打印 warning，不会因为缺 key 变红。

## 回归集

20 条固定任务，来自 [data/regression_tasks.json](../data/regression_tasks.json)：

- 15 条常规：等距抽样，覆盖 5 类人群
- 5 条边界：无历史、单类目、极简请求、兴趣冲突、限定时效

## 判定规则

**按条数比较，不按百分比**，原因有两个：

1. 浮点误差：`0.75 - 0.70 = 0.050000000000000044 > 0.05`，会把「等于阈值」判成「超过」
2. 20 条样本下 **1 条 = 5 个百分点 = 阈值本身**，按百分比判等于「任何一条抖动都失败」

现行规则：**下降超过 2 条才失败**。

## 实测：噪声有多大

同一份代码（未做任何改动）连跑三次：

| 次数 | 成功率 | 通过条数 |
|---|---|---|
| 1（基线） | 75.0% | 15/20 |
| 2 | 70.0% | 14/20 |
| 3 | 85.0% | 17/20 |

**极差 15 个百分点**。来源是 LLM 生成的随机性（temperature 0.7）+ 判定的随机性
（可解释性维度重跑 kappa 会差 0.045，见 [eval/REPORT.md](../eval/REPORT.md)）。

## 所以它的能力边界

| 能挡住 | 挡不住 |
|---|---|
| 改坏 prompt（实测 75% → 45%，下降 30pp） | 3–5 个百分点的缓慢退化 |
| 换模型后明显变差 | 单条任务的偶发失败 |

**要检测细微退化**，需要至少一项：

- 把回归集扩到 100 条以上（成本 ×5，单次约 ¥0.55）
- 同一批跑 3 次取均值（成本 ×3）
- 固定 `temperature=0` 降低生成方差（但仍非完全确定）

## 成本

| 项 | 金额 |
|---|---|
| 单次回归（20 条） | 约 ¥0.11 |
| GitHub Actions（公开仓库） | 免费 |

## 怎么用

```bash
# 本地跑一次，与基线比较
python -m eval.regression

# 更新基线（确认本次是"好"的结果后）
python -m eval.regression --update-baseline

# 冒烟（只跑前 5 条，样本数不同会自动跳过比较）
python -m eval.regression --limit 5
```

## 覆盖率的准确口径

CI 里卡的那条 `--cov-fail-under=60`，说的是**语句覆盖率（statement coverage）**，不是分支覆盖率。

| 口径 | 含义 | 本项目实测 | 是否卡线 |
|---|---|---|---|
| **语句覆盖**（默认） | 可执行语句被执行过的比例 | **85.82%**（395 条中 339 条被执行） | ✅ 卡 60% |
| 分支覆盖 | `if/else`、循环等每个分支方向都走到 | 84.6%（395 语句 / 88 分支 / 11 个分支只走一半） | ❌ 未卡 |
| 条件覆盖 / MC/DC | 复合条件里每个子条件取真取假 | 未测量 | ❌ |
| 路径覆盖 | 所有执行路径组合 | 未测量（组合爆炸） | ❌ |

**为什么默认是语句覆盖**：`pytest-cov` 底层是 `coverage.py`，不加 `--cov-branch` 时只统计语句。
本项目没有 `.coveragerc` / `setup.cfg` 去改默认行为。

**语句覆盖的局限**（必须知道）：

```python
if user.age > 18:
    allow()      # 测过
else:
    deny()       # 没测过
```

只要 `if` 那一行执行过一次，语句覆盖就算这行「覆盖」了——**即使 `deny()` 从没跑过**。
这种缺陷只有分支覆盖能发现。

**所以「85.82%」的准确说法是**：`app/` 目录下 395 条可执行语句中，有 339 条在测试中被执行过。
不代表所有分支都测过，也不代表断言有效。

**什么算一条语句**：赋值、函数调用、`def`、`if` 的条件行、`return`、`raise`。
**不算**：空行、注释、docstring、`else:` / `try:` 这类纯结构行。

## 覆盖率门槛放在哪

| 位置 | 命令 | 行为 |
|---|---|---|
| 本地 | `pytest` | 显示覆盖率，**不卡线** |
| CI | `pytest --cov-fail-under=60` | 低于 60% 直接失败 |

原因：本地经常只跑单个测试文件（`pytest tests/test_llm.py`），此时全项目覆盖率必然很低，
如果本地也卡线，会出现「7 passed 但 exit 1」的误判——这个坑在 2026-11-05 实际踩到过。
