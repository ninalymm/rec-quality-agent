# 三个失败案例

> 面试材料。每个案例都按「为什么失败 / 怎么发现 / 改了什么 / 教训」四段写，
> 全部来自这个项目真实发生过的事，不是编的。

---

## 案例一：三个维度都能用代码算，judge 无事可做

### 为什么失败

最早的 rubric 定义了三个维度——时效性、兴趣相关性、内容多样性。
它们全部可以**用代码精确计算**：日期差、类目命中、类型个数。

于是 judge 拿到的任务是「判一个已经被算出来的结论」，它只能照抄。
**测到的不是判断能力，是复述能力。**

### 怎么发现

跑 judge ↔ 代码计算的一致性，得到 **kappa = 1.000**，完全一致。

这个「完美结果」本身就是错误信号，因为：
- 两个独立的判断者不可能 100% 一致
- 如果完全一致，说明其中一个没有独立判断

### 改了什么

增加第四个维度「**理由可解释性**」——判断推荐理由是否**既引用了用户历史里的具体标题、又说明了关系**。

这个判断无法用代码做，只能靠语义理解。加了它之后，judge 才开始有真正的判断成分。

### 教训

> **一致性过高是设计错误信号，不是质量信号。**

kappa 1.0 说明你在测「抄得准不准」，不是在测「判得对不对」。
评测设计的第一件事，是确保被评测的对象**有判断空间**。

## 案例二：模型自编发布日期，时效性维度失效

### 为什么失败

最初的设计是让模型**自由生成**推荐：标题、类目、发布日期全由它写。

检查生成结果时发现，`published_at` 几乎全是「最近几天」——
模型为了让推荐看起来「有时效性」，会**主动编一个近期日期**。

于是时效性维度拿满分，但这个满分毫无意义：

```
你以为在测：推荐内容的时效性
实际在测：  模型编日期编得像不像
```

### 怎么发现

把生成结果的 `published_at` 和候选池里的真实日期对比，发现对不上；
进一步检查发现，相当一部分是超过今天的「未来日期」。

### 改了什么

引入**候选池**（80 条，8 类目 × 10）：模型只能从池子里选 id，**不许自己写标题、类目、日期**。

```
模型输出：{"id": "C023", "reason": "..."}
代码填充：title / category / published_at 全部从池子查表
```

### 教训

> **模型擅长判断，不擅长搬运。**

凡是「数据本来就在某处」的字段，都不该让模型生成——它生成得越像，你越容易把幻觉当成能力。

## 案例三：judge 单向偏宽，kappa 0.300 但从不误杀

### 为什么失败

用 51 条人工盲标算 judge ↔ 人工一致性，kappa 只有 **0.300**（低于 0.4 的常用门槛）。

乍看是「judge 不准，不能用」。

### 怎么发现

不看单一数字，画**混淆矩阵**（行=人工，列=judge）：

```
             judge0  judge1  judge2
人工 0           8      10       4
人工 1           0      10      11
人工 2           0       0       8
```

**左下三角全是 0**：judge 从来没有给出比人更低的分数。

| 方向 | 条数 |
|---|---|
| judge 更宽 | **25** |
| judge 更严 | **0** |
| 一致 | 26 |

而且人工判 2 分的 8 条，judge **全部同意**。

### 根因

1. 判定标准比人松：人要求「说明关系」，judge 只要提到标题就给高分
2. 模型裁判的配合性倾向：倾向于为一次判定找正面理由
3. 2 分档饱和：分布挤在高分端

### 改了什么

- 把判定标准写成 v2：明确「只提标题不说明关系 → 判 category」，并给出负例
- 但改完 judge↔judge 一致性升到 0.485，judge↔人工仍是 0.300
- **接受这个结果，转而改变使用方式**：把 judge 定位成「粗筛器」，不用于判不合格

### 教训

> **一致性低要分方向。方向决定了它还能不能用。**

- 随机不一致 → 不能用
- 单向偏宽 → 可以当「确认器」：它说不合格基本可信，它说合格要人工抽检
- 单向偏严 → 也可以当「预警器」：宁可多报警，人工再筛

只看 kappa 会得出「不能用」的结论；看混淆矩阵才能得出「怎么用」的结论。

## 三个案例的共同点

| 案例 | 表面现象 | 真实问题 |
|---|---|---|
| 一 | judge 一致率 100% | 设计里没有判断空间 |
| 二 | 时效性满分 | 测的是模型编日期的能力 |
| 三 | kappa 0.300 | 偏差单向，可修正而非不可用 |

**共同点：表面上都是「指标很好/很差」，实际上都是「指标测错了对象」。**

评测这件事，最难的不是算分，是确认「你算的这个分数，到底在衡量什么」。
