### S001

4 条命中(技术2+健康运动2)，第 5 条职场是探索位；类型 3 个；全部 30 天内；5 条理由都指向具体历史条目。典型的满分结构。

### S002

关键案例：总分 6 分看起来不错，但 5 条全是「职场」，类型数=1 → 维度3 得 0 → 不通过。这就是「均 ≥1」规则的意义。

### S003

日期在 31–60 天档 → 维度1 得 1；类型 2 个 → 维度3 得 1；理由全是「根据您的历史行为」→ 维度4 得 0。

### S004

published_at 全缺失 → 维度1 记 null，不参与判定与总分；其余三维均 ≥1 → 通过但标记 partial。这是「不拿数据质量扣推荐分」的实例。

### S005

类型 3 个（教育/娱乐/理财）→ 维度3 得 2，看似不错；但命中只有 3 条（教育2+理财1）→ 维度2 得 1；理由多为空泛 → 维度4 得 0 → 不通过。

## 这组样例覆盖了什么

| 维度1 | 2 分 / 1 分 / null 三种都有 |
| 维度2 | 2 分 / 1 分都有 |
| 维度3 | 2 分 / 1 分 / 0 分都有 |
| 维度4 | 2 分 / 1 分 / 0 分都有 |
| 聚合 | 满分、达标、不达标、partial 四种都有 |

如果你打的分和答案差 ≥2 分，先看是哪个维度，再回头看 rubric 那一节的锚点是否够清楚。
